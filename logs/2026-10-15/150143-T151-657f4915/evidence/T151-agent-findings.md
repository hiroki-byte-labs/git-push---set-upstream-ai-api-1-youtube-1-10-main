## Proposed development tickets

### A. Preserve the meaning of ordinary diagrams in Remotion — P1

**Confirmed incomplete implementation.** `motion-lab/src/PlanVideo.tsx:164–200` renders only compare headings, dropping `leftItems/rightItems`; `:215–220` falls back to five people for `number`, dropping its value/label/note. At `:110–117`, meter values are remapped from signed changes to positive lengths, with a 0.05 floor, and the aggregate row is absent. Native explicitly renders the number, comparison contents and signed meter/mean (`scripts/render.swift:210–234,253–288`). The Plan contract specifies signed relative meter values (`src/plan.ts:14–15,37–45`). This can omit the actual evidence or change the visual meaning of a decrease into a positive bar.

**Coverage/dedup:** T043/T106 cover existing diagram semantics; T126 integrated Remotion but is done. T145/T150's illustration branch bypasses these ordinary diagrams (`PlanVideo.tsx:106–108`); adding motifs does not repair them. T040's broad diagram umbrella already delegates basic types to T041–T044; propose a renderer regression repair, not another diagram expansion project.

**Smallest boundary:** implement number, comparison body lists, and the existing signed-meter/aggregate contract in Remotion; leave illustration designs and Plan schema unchanged. Dependencies: T126/T106 (done); no TTS, posting or T145 preference dependency. **Acceptance:** a compact fixture covers nonempty comparison lists, value/label/note, negative/zero/positive meter values and aggregate. Component/content checks plus isolated decoded start/final frames show every required field and correct signed/aggregate meaning in both renderers. Timing belongs to C; sizing belongs to D. No arbitrary silhouette fallback for a supported diagram type.

### B. Carry source references and factual-status labels into Remotion — P1

Native draws those badges and source title/number fallback (`scripts/render.swift:344–350,371–376`); T072 specifies on-screen references. **Coverage/dedup:** T072 is done; T124/fact-check Skill support claim verification, not rendering of its labels. T150 concerns scene vocabulary. No unfinished ticket specifically restores these missing Remotion overlays. Do not expand this into automatic truth adjudication or a new citation database.

**Smallest boundary:** pass the existing source numbering/catalog, fictional flag, reflection role and demo/production context through props; draw the corresponding compact labels. Dependencies: T072/T104/T126 (done). **Acceptance:** sourced, unsourced, fictional and demo-reflection cases render the correct distinctions; multiple sources and long titles use the same numbers as `sources.txt`/metadata. Inspect decoded frames at 720p/1080p with no caption interference; demo reflection must never acquire a human-authored label. Use D's measurements when available. Human source verification remains separate.

### C. Honor subtitle mode and Plan timing throughout Remotion — P1

**Confirmed incomplete implementation; actual defect magnitude not freshly measured.** `src/remotion-visual.ts:40` does not pass subtitle mode into props; `PlanVideo.tsx:88–97` always burns active cues, so `--subtitles soft` still burns text. Ordinary diagrams use hardcoded frame starts (`:117,124–133`) instead of `diagram.reveal`; compare/branch appear without their staged reveal. Header/ordinary-diagram motion also ignores `style.transitions=false`, whereas illustrations receive it (`:18–28,106–108`). Native uses reveal times and the transition switch (`src/timeline.ts:35–40,63–83`). Finally, props round each cue duration independently (`motion-lab/src/remotion-plan.ts:41–50`), while VTT uses cumulative seconds (`src/commands/sample.ts:90–99`); rounding error can accumulate within a scene. `BurnInSubtitle.tsx:21–25` assumes two six-frame fades even for the valid 0.5-second minimum cue (`src/plan.ts:228`), leaving no full-opacity hold at 24fps.

**Coverage/dedup:** T044/T078/T079/T106 are done; T145 fixes illustration clocks, not ordinary diagrams; T127 checks audio-slice durations, not these rendered boundaries. T028/T077 are about real speech generation/control. This is a local rendering-contract repair, not TTS alignment work.

**Smallest boundary:** shared cumulative frame boundaries, explicit burn/soft/both visibility, reveal-driven ordinary-diagram timing, transition-disable propagation and duration-safe caption fades. Dependencies: T044/T079/T106/T126 (done). **Acceptance:** burn/soft/both produce exactly their requested burned text/track combinations; fractional-second cues tile each scene with no gaps/overlaps and boundaries within one frame of VTT; delayed reveal, transition-off and minimum cue cases are checked at before/on/after frames at 24/30fps. Confirm in decoded output and browser soft-track selection; unavailable browser checks remain unverified. No real narration-quality claim.

### D. Make Remotion text layout resolution-aware and actually measured — P1

**Known limitation plus concrete incomplete implementation.** `PlanVideo.tsx:47–50,61,76–79,94` uses fixed pixel positions/font sizes for both 1280×720 and 1920×1080; `BurnInSubtitle.tsx:34–54` has wrapping width but no measured line/height fitting or two-line limit. `SuperstarIllustration.tsx:19,33` similarly has a fixed canvas/text size. Yet `src/remotion-visual.ts:110–116` writes invented title/caption bounds and contrast values, for only cue 1, independent of the actual DOM. `src/layout.ts:3,8–14` expects native logical coordinates; `src/readability.ts:15–28` trusts supplied measurements. The current report therefore cannot establish that long titles, later captions or diagram labels fit. This is not a claim that every current short sample visibly clips.

**Coverage/dedup:** T091/T106 introduced native fitting/checks; T144's requested white, frameless captions are implemented and should remain. SPEC explicitly acknowledges fixed Remotion layout reports (`docs/SPEC.md:33–34`), but no unfinished ticket repairs them. T150's label-width fix is native-specific and short-frame inspection is not all-text measurement.

**Smallest boundary:** establish one Remotion coordinate/scale convention; measure actual rendered text boxes/font sizes/background contrast, fit/wrap within explicit zones and report all cue/title/diagram/source-label cases. No new subtitle style decision. Dependencies: T126 (done); coordinate with A/B/C, but geometry work can begin independently. **Acceptance:** 720p/1080p stress fixture with 30-character titles, 55-character captions, later long cues and maximal diagram/source labels. Measured reports match rendered content and detect an intentionally overflowing case; decoded frames show captions within the intended one/two-line area and readable at both sizes. Missing measurements must not become a fabricated pass. Phone/TV preference validation stays human-gated.

T150's recorded independent decode is similarly a check on its four artifacts. T129 uses fake MP4. No unfinished ticket owns truthful Remotion media inspection.

**Smallest boundary:** factor renderer-independent completed-MP4 verification for decode, measured frames/durations, required streams and measured audio levels, then call it from Remotion. Keep native image-reference PSNR renderer-specific; do not impose natural-speech loudness targets on confirmation tones. Dependencies: T126 (done). **Acceptance:** good local synthetic MP4 passes with command/results and measured-vs-expected fields; truncated/wrong-duration/missing-audio/failed-inspector cases fail or explicitly remain unverified, never `passed`. Failed required checks prevent `video-checked` completion. A short isolated real Remotion artifact is inspected independently to verify the integration. No external service needed.
