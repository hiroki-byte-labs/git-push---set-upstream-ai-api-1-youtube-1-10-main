24: ## 動画生成と再生
25: ```sh
26: ./scripts/run src/cli.ts sample                                   # M1の36秒（v1台本）
27: ./scripts/run src/cli.ts sample --plan fixtures/sample-v2.json    # v2台本（図解4種・48秒、旧テーマ）
28: ./scripts/run src/cli.ts sample --plan fixtures/sample-general.json  # 新テーマ（一般・68秒、導入文と出典つき。開発用の架空例）
29: ./scripts/run src/cli.ts sample --plan fixtures/sample-v2.json --renderer remotion  # 本体に統合済みの任意renderer（T126）
30: ./scripts/run src/cli.ts sample --plan fixtures/layout-stress.json --resolution 1080  # 文字配置の検査用（長い見出し・二行字幕）
31: ./scripts/run src/cli.ts lint --plan 台本.json                    # 安全検査だけ
32: ./scripts/run src/cli.ts serve
33: ```
34: ブラウザーで http://127.0.0.1:4173 を開くとジョブ一覧が出ます。詳細画面で再生、検査結果の確認、版に結び付く承認・差戻しができます（投稿はしません）。字幕の既定は焼き込み（burn、T106で利用者の希望により変更）で、切り替え式は `--subtitles soft`、両方は `both` です。ジョブ管理は `jobs` / `jobs clean`、確認の記録は `review` です（docs/OPERATIONS.md）。停止はCtrl+Cです。サーバーはローカルのみ。生成後の再生にインターネットは不要です。CLIは必ずリポジトリルートを使います（scripts/runが移動します）。npmを利用する環境では `npm run sample` なども使えます。
35: 
36: 台本の`theme`は`general`（日常の知識）か`investment`（投資）。未指定は旧形式として投資扱いで、最終場面に推奨・保証を否定する免責が必要です。一般テーマは「結果を保証しない」旨の否定文が必要で、投資の語（銘柄・株価・NISA等）を含めば投資の免責も必要です。`intro`（導入文）は概要欄の先頭に入り、出典は文献名・URL・確認日と使用場面を`metadata.json`の`sources`に保存します（URLの記載は主張の検証済みを意味しません）。詳細はprompts/script.mdとADR-017。
37: 
38: `outputs/<job-id>/sample.mp4` が完成動画。字幕は既定で映像に焼き込み、別ファイル `subtitles.vtt` も作成します（`--subtitles soft` で切り替え式の字幕トラック、`both` で両方）。文字配置の検査結果は `job.json` の `layout`（T106）。`plan.json`、`job.json`、`lint.json`、`metadata.json`、`media-check.json`、サムネイル3案、全場面の確認画像も出力。`outputs/latest.json` は最後に正常完了したジョブを指します。2回実行しても既存出力は上書きせず新しいジョブになります。視聴する確認音は各場面の冒頭だけです。字幕を読み上げる機能はまだありません。

40: ## 本人の工程を通す制作（T104）
41: T084の判断前チェックリストは、台本の`practice`で指定した原文から各ジョブのテキスト・PNGと概要欄を生成します。末尾の案内は`role: action`。形式と検証制約は [チェックリストの使い方](docs/T084-CHECKLIST.md) を参照（実再生確認待ちでT084はreview）。
42: 
43: `sample` は常に**デモ**（本人の題材選定・考察・台本承認を経ていない試作）です。本番の動画は制作案件（`produce`）からだけ作ります。各工程は確認画面（`serve` → 一覧の「制作案件」）からも操作できます。
44: 
45: ```sh
46: # 1. エージェントが題材候補（ニュース・事象の入口、概念、具体例）を用意し、案件を作る
47: ./scripts/run src/cli.ts produce new --candidates 候補.json --by 'エージェント名'
48: # 2. 本人が題材を選ぶ（記録者名は本人。本番の案件ではエージェント名を拒否）
49: ./scripts/run src/cli.ts produce select production-xxxxxxxx --candidate price-index --by '本人の名前'
50: # 3. 本人が考察を書く（ファイルか本文）。この文章がそのまま台本の考察の場面に入る
51: ./scripts/run src/cli.ts produce reflection production-xxxxxxxx --file 考察.txt --by '本人の名前'
52: # 4. エージェントが下書き（role: reflectionの場面を1つ持つ台本）から台本を作る
53: ./scripts/run src/cli.ts produce script production-xxxxxxxx --plan 下書き.json --by 'エージェント名'
54: # 5. 本人が台本を読み、表示された「台本の版」で承認（または理由つきで差戻し）
55: ./scripts/run src/cli.ts produce script-review production-xxxxxxxx approve --hash 台本の版 --by '本人の名前'
56: # 6. 制作（台本が承認済みでなければ不足を表示して拒否）
57: ./scripts/run src/cli.ts produce render production-xxxxxxxx --subtitles burn
58: # 7. 本人が完成動画を確認画面で見て承認・差戻し（review <ジョブ> でも可）
59: ./scripts/run src/cli.ts produce status production-xxxxxxxx
60: ```
61: - 題材・考察・台本が変わると台本承認は失効し、古い台本から作った動画は「承認失効」になり承認もできません。運用記録の追記では失効しません。
62: - 考察をエージェントが整えた場合は `--assisted-from 元の版` で整形版として記録し、本人の原文と区別します。
63: - 試験・デモは `produce new --demo` の案件で、記録者をtest-agent等にします。デモの承認は本番に転用できません（`review <ジョブ>` の「公開前の判定」で確認）。modeのない既存ジョブはデモ（旧ジョブ）扱いです。
64: - 記録者名は自己申告で認証ではありません。投稿は引き続き無効です。
65: - T106の構成案（導入→身近な例→仕組み→本人の考察→活かし方→まとめ）の下書きは `fixtures/draft-price-index.json`。集計の図（meter）と経緯の矢印（travel）、説明に合わせた段の表示（reveal）を使っています。構成案と参考動画の観察は [docs/T106-DESIGN.md](docs/T106-DESIGN.md)。

164:   slices: AudioSlice[],
165:   bgmVolumeDb = -18,
166:   duckedVolumeDb = -28
167: ): DuckingProfile {
168:   let currentTime = 0;
169:   const duckRangeSec: {start: number; end: number}[] = [];
170:

172:     const dur = s.actualDurationSec ?? s.expectedDurationSec;
173:     if (s.text.trim().length > 0) {
174:       duckRangeSec.push({
175:         start: currentTime,
176:         end: currentTime + dur,
177:       });
178:     }
179:     currentTime += dur;
180:   }
181: 
182:   return {
183:     bgmVolumeDb,
184:     duckedVolumeDb,
185:     duckRangeSec,
186:   };
