## 記録の信頼範囲
- 初回実装ログは会話内の操作・結果と既存ファイルから後日ではなく同日中に再構成した回顧記録。ツールの全出力や会話の完全な逐語録ではありません。
- 元の各操作の正確な時刻は取得できていないため、順序と日付だけを記載。今回新たに記録した時刻はmetadata.jsonに保存します。
- 「Codex / GPT-6 Astra」は今回ユーザーが指定した記録者・モデル名。モデル実行基盤のIDを独立に検証した記録ではありません。
- 推測を実績に置き換えません。自然なナレーションと実再生は未確認・未実装のままです。
- 元作業で出た16チケットは、ログ整備T009追加後は17件になります。過去の16件成功という記録を書き換えません。

## 今後の追記
`YYYY-MM-DD/連番-作業名/` を新規作成。TEMPLATE.mdを使い、記録者・モデル・日時・依頼・対象チケット・変更・検証・残件・再開手順・参照元を残してください。過去ログの訂正は新しい記録から訂正箇所と理由を参照し、過去の結論を黙って上書きしません。

キー、トークン、秘密値、本番データ、動画本体、無選別な環境変数ダンプは保存しません。コマンド出力は必要なものだけ確認して保存。制作ジョブ全体はoutputsに置いたままにします。

## T010以降の共通運用
新規ログは[共通ワークフロー](../docs/AGENT-WORKFLOW.md)のstart/finish/checkで管理します。任意のエージェント名を指定し、モデル名の情報源も記録します。新形式はUTCの日付/時刻を使い、session.jsonに機械検証情報を保存。過去の作成者表記と回顧記録は履歴として維持します。入口は[CONTRIBUTING.md](../CONTRIBUTING.md)とAGENTS.md。テンプレートの手動コピーだけでは終了検査を通りません。
