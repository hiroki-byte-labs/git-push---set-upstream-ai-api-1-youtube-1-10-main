## 目的
承認された範囲でローカル収集機能が利用できるよう、専用プロジェクトと最小権限の認証手段を人が選定・準備する。
## 実施範囲
T131の調査結果を読み、必要なAPI有効化、キーまたはOAuth方式、キー制限、利用者・同意の要否、クォータ表示を確認する。値そのものはチケット・Git・チャット・ログに記録しない。
## 対象外
キー値の受け渡し、投稿権限の付与、未承認の実API呼び出し、課金プラン変更。
## 受け入れ条件
- 利用する認証方式と承認範囲、クォータ上限、制限状態が秘密値なしで記録される。
- 認証値は利用者のローカル秘密管理にのみ置かれ、後続が環境変数名など非秘密の参照方法を使える。
- T131で必要性が否定された場合は、理由を記録して認証作成を行わず完了できる。
## 検証方法
Google Cloudの設定画面で構成状態とAPI制限を確認する。キー値を表示・コピー・ログ保存しない。

未実施。

T131は完了（2026-10-13）。人が着手可能（ready）。下の「T131の結果に基づく具体化」に従って判断する。認証や課金範囲に疑義があれば停止する。
## 所要時間
30〜60分（Cloud審査・反映待ちを除く）
## 操作手順
1. T131の調査文書と推奨最小権限を確認する。
2. 利用者が対象プロジェクト/APIの作成・有効化を判断し、承認範囲だけ設定する。
3. キー制限とクォータを確認する。キー値は表示せず、Git対象外の秘密管理に保存する。
4. 認証方式、設定状態、残る人判断を秘密値なしでチケットへ記録する。

### T131の結果に基づく具体化（2026-10-13、Claude Code。実施は人）
- 必要な認証は**APIキーのみ**（公開データの読み取り。OAuth・同意画面は不要）。docs/RESEARCH-TRENDS-API.md 2章。
- Google Cloudで分析専用のプロジェクトを使い（III.D: API Clientごとに専用プロジェクト）、YouTube Data API v3だけを有効化する。キーの「APIの制限」をYouTube Data API v3に限定する。課金アカウントの紐付けは不要（無料枠10,000 unit/日）。
- キーは環境変数 `YOUTUBE_API_KEY` で渡す（例: シェルの秘密管理やパスワード管理ツールから読み込む）。リポジトリ・`.env`のコミット・チャット・ログに書かない。
- 次の3点を判断し、秘密値なしでこのチケットに記録する。
  1. APIキーを作るか（作らない場合は理由を書いて完了。T134は模擬接続のまま）。
  2. 実データで成長指標・カテゴリ集計を使うために、Quota and Compliance Audit と派生指標の修正条項（III.L、https://developers.google.com/youtube/terms/derived-metrics-policy ）を申請するか。申請しなければ、実データは「取得から30日以内の取得値の時点つき表示」（`report series`）だけに使う。
  3. 申請・承認された場合は、承認の参照（受付番号など、秘密でないもの）を `./scripts/run src/trends-cli.ts policy set --profile audited-derived-metrics --approval-ref <参照> --by <名前>` で記録する。カテゴリ集計はIII.E.2（事業動向把握目的の集約禁止）への該当性を判断したうえで `--category-aggregation` を付ける。
- 最初の実接続の承認範囲を決める（例: 地域JP、全体チャート1ページ、カテゴリ表なし、5 unit以内）。`collect --live --dry-run` で見積りを確認してから、エージェントに1回の実行を依頼する（T134の残件）。
## 成功時の状態
後続実装が秘密値を知らずに参照できる認証手順と設定状態が確認済み。
## 困った場合の対処
費用、規約、権限、審査が不明なら操作を中止し、秘密値を含めず不明点を記録する。
