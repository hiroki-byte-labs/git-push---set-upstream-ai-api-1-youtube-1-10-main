## 目的
複数のローカル制作案件を安全に順番処理し、失敗・中断後に既存成果物を保護して復旧できるようにする。
## 実施範囲
ローカルキュー、同時実行数上限、状態永続化、失敗隔離、有限再試行、完了済み工程の再利用条件、再開と成果物ハッシュ検証を実装する。
## 対象外
クラウド/常駐ワーカー、無人投稿、自動公開、実API課金。
## 受け入れ条件
- 並行数上限を超えず順序・状態が記録される。
- 異常終了後の再開で完了成果物を上書きしない。
- 重複投入・不明費用・破損状態では安全停止する。
- 合成ジョブで正常・失敗・再開・復元を再現できる。
## 検証方法
一時ディレクトリの複数模擬ジョブと異常注入テスト。

利用例（専用の一時領域、合成入力、mock工程。MP4生成や実接続ではない）:
```ts
import {mkdtempSync, writeFileSync} from 'node:fs';
import {tmpdir} from 'node:os';
import {join} from 'node:path';
import {LocalQueue} from './src/local-queue.ts';
const work = mkdtempSync(join(tmpdir(), 'local-queue-'));
const input = join(work, 'input.json');
writeFileSync(input, JSON.stringify({schema: 1, mock: true, executorVersion: 1}));
const queue = LocalQueue.open(join(work, 'queue'), {concurrency: 2});
try {
  queue.enqueue({id: 'mock-one', mode: 'mock', inputs: [input], stages: ['audio', 'video'], maxAttempts: 3});
  await queue.drain(async ctx => {ctx.writeArtifact('mock.json', JSON.stringify({mode: 'mock', stage: ctx.stage}));});
  console.log(queue.snapshot());
} finally {queue.close();}
```
Executorはlocal/mockだけで、成果物を書き込む副作用はctx.writeArtifactに限定する。実装版・設定など再利用に影響する全情報をinputsに含める。ファイル名は拡張子を使用可、receipt.jsonは予約。既存成果物を読み出す場合はqueue.rootとctx.previousのfileを結合する。制作案件はenqueueProduction(root, id, stages, 'mock'|'local', maxAttempts)を使用する。工程関数は呼出側で提供する契約であり、既存レンダラーの自動起動・既存T128成果物の自動インポートは行わない。

中断復旧: 同じ一時領域とconcurrencyでopenしrecover→drain。ownerが残る場合は元プロセス停止を確認し、openのrecoverDeadOwner:trueを指定する（ESRCHだけで回収、生存PID/EPERM/壊れたownerは拒否）。PID再利用時は自動回収しない。回収そのものが中断してrecovery.lockが残った場合は全利用者を停止し、状態・成果物のコピーを保全してから人がlockを調査する。破損状態・unknown・failed/blockedは自動修復/再送しない。キューはtrustedなローカル関数の制御で、任意JS関数のネットワークアクセスを隔離するsandboxではない。停電・媒体故障、実動画制作、実サービスの費用照合・復旧は未検証。T050の無人運用や投稿機能は含めない。
