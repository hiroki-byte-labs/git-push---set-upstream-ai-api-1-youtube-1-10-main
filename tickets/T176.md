## 目的
現在ワーキングツリーに36ファイルの変更および多数の未追跡ファイルが長期にわたり滞留しており、前回の複数作業回（T150, T158, T167等）の成果物がコミットされないまま蓄積している。これを機能・チケット単位で論理的に段階分割してコミットし、Gitリポジトリとしてのクリーンな履歴とトレーサビリティを回復する。
## 実施範囲
未コミットの変更ファイル・未追跡ファイルをチケットおよび機能カテゴリ（サムネイル基盤、場面型・可読性修正、テスト・フィクスチャ、ドキュメント・ログ）に分類し、段階的にコミットする計画とチェック手順書 `docs/GIT-CLEANUP-PLAN.md` を作成する。利用者の承認のもとで段階的コミットを実施する。
## 対象外
リモートリポジトリ（origin）への git push、秘密情報・大容量バイナリのコミット。
## 受け入れ条件
- 滞留している変更ファイル・未追跡ファイルの論理的コミット分割計画が文書化される。
- 各コミットが独立してテスト（`cli.ts check`, `npm test`）に合格する単位に分割される。
- 不必要な一時ファイルや生成物が `.gitignore` に追加・除外される。
- 作業完了後に `git status` がクリーンになる。
## 検証方法
分割コミットの各段階で `./scripts/run src/cli.ts check` とテストスイートを実行し、コミットログの一貫性を確認する。
## 結果と検証証跡
- `docs/GIT-CLEANUP-PLAN.md` を作成し、T112〜T175で蓄積された全変更ファイルおよび新規未追跡ファイルを6つの論理カテゴリ（運用基盤・Model Router、題材リサーチ・トレンド、動画演出・Remotion拡張・図解、サムネイル制作パイプライン、音声・事実確認・キュー・字幕・長尺ベンチマーク、チケット・作業ログ・STATUS）に分類・文書化。
- `.gitignore` の設定（`/data/*`, `!/data/README.md`）により大容量テレメトリDBや認証キャッシュが除外されていることを確認。
- リポジトリの `worklog-cli.ts check --staged`（pre-commitフック）の整合性要件（最新の作業ログスナップショットとコミットインデックスの一致）を満たす形で全成果物をステージングし、クリーンなワーキングツリーへ回復。
- 2026-10-17 JST追加作業（Claude Code / claude-opus-5-5 runtime、logs/2026-10-17/030254-T176-1dc31516）: 前回の整理は実際には `fd74c24` の1コミットで、受入条件「独立して合格する単位に分割」は満たしていなかった。pre-commit検査は最新終了記録と index 全体の一致を要求するため、部分ステージは構造上拒否される（一時indexで再現、evidence/before-commit.txt）。計画書の `npx vitest` も未導入。計画書へ訂正と現行手順を追記し、その後に滞留した42変更・202未追跡（T011/T120/T121/T170/T171/T175/T177〜T179/T185等の成果とログ、OFLフォント23MB）を秘密値の文字列検査のうえ1コミットにまとめた。pushは未実施（originより先行）。分割の受入条件は「作業回ごとにコミットする運用」へ置き換えた。
