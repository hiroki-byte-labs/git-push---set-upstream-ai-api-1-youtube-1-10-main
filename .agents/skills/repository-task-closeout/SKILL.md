# チケットとログを揃えて作業を閉じる

対象リポジトリのルートを確認し、AGENTS.mdとdocs/AGENT-WORKFLOW.mdを読む。ここで示すパスはそのルート基準であり、Skillのインストール先基準ではない。CLIのオプションや制約はリポジトリの正本を優先する。

## 作業回を確認する
すでに自分が使っている未終了sessionがあれば、それを使う。別の作業のopen記録を黙って終了・削除しない。対象が未開始なら、既存チケットと依存を確認し、正本のstartコマンドで実施者・モデルとその情報源・依頼を記録する。モデル不明はunknown。

同じ作業ツリーで、複数のエージェントが同時に動くことがある（T112・T113・T120で発生）。
- 長時間更新がない未終了の記録も、放棄されたとは限らない。T112では、10時間動きのなかった記録が、確認の数分後に別のエージェントの手で閉じられた。他者の記録を中断扱いで閉じる前に、`find . -newer <session.json>` や `ls -lT` で直近数分の書き込みを確かめ、利用者に確認する。
- 新しいチケット番号を取る直前に、`check` と最新のチケット番号を確かめる。新規ファイルは、上書きしない方法（`set -o noclobber` と存在の確認）で作る。T113では、同時に作られたチケットを別のエージェントが上書きし、元の内容を復元できなくなった。
- 衝突に気づいたら、それ以上書き込まずに利用者へ知らせる。他者の作業ディレクトリに自分の証跡を置かない。

この仕組みのないリポジトリでは適用対象外とし、既存の終了規約に従う。新しい仕組みの導入は別の依頼として扱う。

## 変更を先に揃える
1. 今回の変更に必要な検証だけを実行し、実際の結果を保存する。以前の試験結果を今回の結果へ読み替えない。人待ちや未検証を明示する。
2. チケットに変更・結果・証跡・残件を反映。受け入れ条件未達ならdoneにしない。人の確認待ちはreview。
3. docs/STATUS.mdに次の作業・制約・再開方法を書く。
4. 現在のWORKLOG.mdの必須節を埋め、必要な検証出力を同じ作業ディレクトリへ保存する。秘密情報と動画本体を含めない。
5. 定型作業のSkill化が規約で求められていれば、この時点までに評価・必要なSkill変更を完了する。今回すでに評価済みなら再実施しない。

## 証跡を保存する（T094〜T099の反復から追加）
- 試験・検査の出力は、終了コードを隠さない形で作業回の `evidence/` に保存する。例: `コマンド > evidence/x.txt 2>&1; echo "EXIT=$?" >> evidence/x.txt`。パイプ末尾（`| tail`など）の成功で失敗を隠さない。
- 不具合修正では、先に回帰試験を追加して修正前の失敗を `before-fix.txt` に、修正後の対象試験を `after-fix.txt` に、型検査を `typecheck.txt` に分けて残す。WORKLOGには件数（tests/pass/fail）と終了コードを書く。
- 生成経路の確認が必要でも、既存の制作物（outputs等の除外領域）を増やしたり整理したりしない。必要ならリポジトリの必要部分を一時ディレクトリへ複製して実行し、その出力を証跡にする。
- 作業回がopenの間は `check` が未終了で失敗するため、途中の検証は対象試験と型検査を直接実行する。全体検査はfinish後に行う。

## 記録を閉じて検査する
正本に定めるfinishをcompletedまたはpausedで実行し、その後checkを実行する。作業回completedはチケットdoneと同義ではない。検査が失敗したら理由を調べ、失敗したまま成功報告しない。未記入や変更漏れなら正しい作業回の中で補完する。

特にこの実装では、終了時点のソースとログ本文・添付証跡をハッシュで固定する。**チケット・STATUS・Skill原本・証跡はfinishより前に更新する。** finish後にログへ成功メモを追記すると検査が失敗する。終了後の訂正は新しい作業回に記録する。ログとソースのGitへのステージ漏れにも注意するが、依頼のないcommit/pushはしない。

## コミットする（T015・T110の反復から追加。依頼があるときだけ）
- pre-commitは `worklog-cli.ts check --staged` で、indexの内容が最後に閉じた作業回の記録（作業ツリー全体のハッシュ）と一致することを求める。一部のファイルだけをコミットすると失敗する。
- コミットに含めたくないファイル（利用者の個人設定など）は、削除せず、.gitignoreで除外する変更を新しい作業回で記録してから `git add -A` する。`--no-verify` やフックの無効化で回避しない。
- プッシュ先が公開リポジトリかを確かめ、秘密情報・動画本体の走査結果を証跡に残す。プッシュ先のブランチは利用者に確認する。
- コミットのハッシュは作業回の終了後に決まるため、ログには書かない（git logが正本）。コミット前に `./scripts/verify` を実行する。

## 引き渡す
利用者へ結果、検証、未完了、次の作業を短く伝える。明示的に除外されるoutputs内の引き渡しコピーを作る場合、リポジトリの除外規則を確認し、最後にcheckを再実行する。適用した事実と記録者は現在の作業ログへfinish前に記載する。最終検査の成否はCLI結果を確認して報告する。
