# 定型作業をSkillへ抽出する

実行済みの作業から、次回の判断や操作を実際に改善する手順だけを保存する。Skill作成それ自体を目的にしない。

## 対象を決める
対象リポジトリの作業規約、現在のタスク、関連する作業ログ・スクリプト、利用可能なSkillの名前と説明を確認する。無関係なリポジトリ、秘密設定、全会話履歴を収集しない。

同じ入力→判断→操作→検証が複数回現れる場合、またはユーザーが具体的に再利用を求めた場合を候補にする。一般的な助言より、繰り返し迷う分岐、実際に失敗した順序、検証可能な操作を優先する。候補ごとに次を短く記録する。
- 根拠となるタスク/ログと反復箇所
- 想定する入力・出力・適用条件
- 既存Skill/スクリプトとの重複
- 新規作成 / 既存更新 / 見送りと理由

## 作成・更新する
同目的のSkillがあれば必要部分を更新する。手順が既にリポジトリのコマンドや規約で管理されている場合、正本を参照・実行するSkillとし、コードや規約の全文を複製しない。

利用可能ならskill-creatorの作成・検証手順を読む。未提供の環境ではSKILL.mdにname/descriptionのfront matterと、適用条件、操作、検証、例外時の終了条件を記載する。不明な機能や配置規約を推測しない。

作成先はユーザー指定を優先。リポジトリで共有するものは既存のSkill配置を使い、なければ`.agents/skills/<name>/SKILL.md`を原本とする。個人向け導入は対象ランタイムの対応場所へ行い、既存ファイルを無断で上書きしない。エージェント名や端末固有パスを実行条件にしない。自動発見を保証せず、原本への明示的な読込手順を残す。

補助スクリプトは同じ処理の再実装を減らせる場合にだけ作る。既存コマンドで足りるなら作らない。契約、課金、公開、認証、他者への送信の権限をSkillで追加しない。利用者の許可範囲外の作業が候補になったら、手順だけ記録し実操作は行わない。

## 検証して今回の作業に適用する
形式検査、参照先の存在、残ったひな型、権限の逸脱、機密/個人パスの混入を確認する。作成したスクリプトは実行試験する。利用可能ならskill-creatorのquick_validateを使う。

抽出したSkillを読み、実際の対象作業に適用する。既に開始済みの作業は重複開始せずその状態を引き継ぐ。試用できない外部操作は未検証と明記する。形式検査の成功を実運用の成功と呼ばない。

## 終了と継続
Skill化の判断、変更パス、検証結果、実適用した範囲、未検証、記録者を元タスクのログへ保存する。適切な候補がない場合は見送り理由を残して元の作業を完了する。通常タスクでは最も有効な候補から始め、残りは候補として残す。無制限にSkillを量産しない。

この評価を同じ作業回で再帰的に繰り返さない。Skill作成に付随した手順だけを根拠に、さらに別のメタSkillを作らない。以後の独立した実績から更新する。
