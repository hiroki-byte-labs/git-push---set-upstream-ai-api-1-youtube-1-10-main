# 題材リサーチと根拠資料作成手順（topic-research）

正本は `AGENTS.md`、`docs/REFERENCE-STYLE-POLICY.md`、`docs/AUTONOMOUS-DOCUMENTARY-PIPELINE.md`、`tickets/T122.md`。
このSkillは、動画制作パイプライン（`cli.ts produce`）において、本人が題材を選択（`produce select`）する前に、エージェントが比較検討可能な題材候補と客観的な根拠資料を一定の形式で作成・提供するための共有手順を定義する。

---

## 1. 企画フレームワーク（分析動画群に基づく法則）

知的好奇心を刺激するドキュメンタリー（「考えすぎる葦」10本等の分析）では、以下の設計原理を厳守する。

### 1.1 「日常の素朴な疑問や不条理」×【二重の学術フック】
単なる雑学や俗流解説ではなく、視聴者が日常生活で感じる身近なモヤモヤ（共感・直感）を出発点とし、専門的な学術体系（納得感・権威性）を用いて解剖する。
- **身近な問いの形式**:
  - 「なぜ2位ではダメなのか？」（勝者総取りの不条理）
  - 「なぜあなたの名字は絶滅する運命にあるのか？」（日常的な固有名詞の消滅）
  - 「なぜ差別をなくすほど社会は分断されるのか？」（善意が生む逆説）
- **二重の学術フック**:
  - 単一の学問ではなく、2つの専門領域（例: スーパースター経済学×ネットワーク外部性、確率論・分枝過程×社会統計学、社会心理学×愛着理論）を交差させ、立体的な説明を行う。

### 1.2 3段ストーリー構造（Paradox → Mechanism → Reflection）
1. **直感の解体（Paradox / 0:00〜1:30）**:
   - 常識や直感と反する事実を提示し、「認知的不協和」を生み出す。
2. **構造の解剖（Mechanism / 1:30〜8:00）**:
   - 論文や統計データに基づき、背後にある構造的・数学的・心理的因果メカニズムを解説。
   - 抽象概念を視覚メタファー（スポットライト、順次伸長メーター、因果フロー矢印、ピクトグラム対比）で図解。
3. **日常・内省への着地（Reflection / 8:00〜10:00+）**:
   - 「では私たちはどう向き合うべきか」という個人の処世術・生き方・内省的問いへ着地させる。
   - ※ 本人の考察工程（`produce reflection`）に接続するため、結論をAIが断定せず、本人が思考を深められる余白を残す。

## 2. 情報分類の原則（Fact・Inference・Unverified の厳格分離）

ハルシネーションや不正確な俗説を排除し、信頼性の高い作品にするため、リサーチ内容は必ず3つに分離して記録する。

| 区分 | 定義 | 必須要件 | 記載例 |
|---|---|---|---|
| **事実（Fact）** | 一次文献、公的統計、査読付き論文、実測データ等で確認された確定事項 | 出典（著者・文献名・発表年・URL・確認日）を付記。改変せず原典の数字を用いる。 | Sherwin Rosen (1981) の論文における「才能のわずかな差が天文学的な所得格差を生む市場均衡条件」。 |
| **推論（Inference）** | 学術理論に基づくメカニズムの解釈、モデルの適用、因果関係の論理展開 | 「〜というモデルに基づく解釈」「〜という仮説」と明記し、事実と混同させない。 | 「デジタル配信による限界費用のゼロ化が、現代のクリエイター経済にも同理論を加速させている」という推論。 |
| **未確認（Unverified）** | 俗説、反論が存在する論争的知見、出典が確認できていない数値 | 「未確認事項」として隔離し、台本本文での安易な事実断定を禁止する。 | 「日本国内における特定名字の完全絶滅予測年数（前提条件により計算結果が分かれるため未確定）」。 |

## 3. 成果物の形式仕様

エージェントが題材リサーチを行う際は、以下の2つのファイルを対として作成する。

### 3.1 題材候補JSON（`candidates.json`）
既存の制作パイプライン（`src/production.ts` の `validateCandidates`）に直接投入可能な形式。

```json
{
  "schema": 1,
  "note": "リサーチ目的・実施者・確認日などの補足説明",
  "candidates": [
    {
      "id": "英数字ハイフン40字以内（例: superstar-economics）",
      "title": "タイトル（60字以内。問いの形式と【学術フック】）",
      "hook": "入口の問い（200字以内。日常の疑問や不条理）",
      "concept": "学術概念（200字以内。2つの学術フックとメカニズム要約）",
      "example": "具体例（200字以内。身近な対比や観察可能な現象）",
      "sources": [
        {
          "title": "著者名 (発行年)『文献名』",
          "url": "https://..."
        }
      ]
    }
  ]
}
```

### 3.2 根拠資料レポート（`research-report.md`）
本人が内容を精読し、どの題材を採用するか判断・考察するための詳細ドキュメント。

各候補について以下を記述する:
1. **候補IDと基本情報**: タイトル、問い（日常の疑問）、学術フック。
2. **ストーリー構成案**:
   - Paradox（直感の解体）
   - Mechanism（構造の解剖）
   - Reflection候補（本人が考察するための論点）
3. **二項対立と視覚メタファー提案**:
   - 画面設計（スポットライト、対比カード、ピクトグラム配置、メーター伸長など）。
4. **根拠資料と情報分類（Fact / Inference / Unverified）**:
   - 一次文献（論文・統計）の書誌情報、DOI/URL、確認日。
   - 事実・推論・未確認事項の対比表。
5. **注意事項・制約**:
   - 著作権法第32条（引用要件）の遵守確認、センシティブな表現・禁止表現のチェック。

## 4. 制作パイプラインへの受け渡し手順

1. **候補ファイルの配置**:
   - `fixtures/` または作業ディレクトリに `candidates.json` と `research-report.md` を作成。
2. **新規制作案件の作成**:
   ```bash
   ./scripts/run src/cli.ts produce new --candidates fixtures/candidates-xxx.json --by <作成者名> [--demo]
   ```
3. **本人の選択支援**:
   - 本人に `research-report.md` を提示し、選定を依頼。
   - 本人が `produce select <id> --candidate <candidateId> --by <本人の名前>` を実行。
