# 参考動画の動きを解析・再現・比較する

正本は `motion-lab/README.md`（コマンド、出力、判定基準）と作業規約（AGENTS.md）。Remotionの書き方は `.agents/skills/remotion-best-practices/SKILL.md`（公式Skill、版固定）を読む。ここでは判断の分岐と、T110で実際に起きた失敗だけを書く。

## 1. 入力を確かめる
- 動画は利用者が手元に用意した、利用を許可された素材だけ。取得・ダウンロードはしない。許可の根拠（本人撮影、ライセンス名とURL等）が分からなければ利用者に聞き、`--rights` に記録する。根拠なしに解析しない。
- 元動画の画素・音声・フォント・ロゴは再現に使わない（再現は自作のSVG図形だけ）。音声は対象外。
- 10秒程度に切ってから使う（解析は単色背景の上の重ならない単色図形が対象。対象外の素材なら、その旨を先に伝える）。

## 2. 一括実行する
`cd motion-lab && node tools/lab.ts --run <名前> [--reference <動画> --rights '<根拠>'] --theme both`。Node 24はPATHか、`NODE_BIN` の場所のnodeを直接使う。初回のレンダリングはChrome for Testingを取得する。
- 「Waiting for root component to load」で止まる場合は、雛形でも再現するか確かめる。この端末ではChrome Headless Shellが原因で、`remotion.config.ts` の `setChromeMode("chrome-for-testing")` で解決した。props（解析JSON）やコードを疑う前に切り分ける。

## 3. 結果を読む
`out/<run>/summary.json` → `compare/compare.md` → 比較画像（参考｜生成｜差×4）→ `analysis/analysis.json` の `unresolved` の順に見る。合成動画なら `score.md` も見る。
- 画素の基準に合格していても、動きの比較（生成動画を同じ解析器で測る）で差が出ることがある。両方を見る。
- 差が出たら、まず「参考動画の解析が違う」のか「再現（Remotion側の入力・描画）が違う」のか「生成動画を測るときに解析器がぶれた」のかを分ける。比較画像で差の位置を見て、`analysis.json` と `compare/generated-analysis.json` の該当図形の `series`（フレームごとの実測値）を並べる。

## 4. 直し方の分岐（T110で実際に起きたもの）
- **参考動画で見えていないフレームに像が出る** → 観測できない区間をモデルで外挿して描いていないか。描くのは観測されたフレームだけ（`render.from/to`）。
- **大きさ変化が回転と判定される** → 主軸の長さが一定かを確認する（回転なら変わらない）。
- **フェードの始まり等で大きさ・位置がぶれる** → 背景との差が小さい観測を幾何に使っていないか。
- **角丸を矩形と判定する** → 面積比ではなく角の深さで半径を見る。
- **開始時刻のモデル値が実行ごとに大きく変わる** → その値は識別できていない（不確かさが大きい）。判定にも報告の断定にも使わず、`upper_bound` と見え始めで扱う。
- 判定を通すためだけに基準や比較方法を緩めない。比較方法を変える場合は、なぜその量が比べられない（または比べるべき）かを、観測できる・できないの根拠で説明し、ログに残す。

## 5. 記録する
- 1回目の比較（修正前）の `compare.md` と、修正後の比較を両方証跡に残す（テキストのみ。mp4は入れない。比較画像PNGは必要な少数だけ）。
- 単体試験（`node --test tests/*.test.ts`）、型検査（`pnpm run typecheck` 相当）、`eslint src` を実行して件数と終了コードを書く。
- 観測できなかった項目と、実在の参考動画で未検証であることを明記する。
