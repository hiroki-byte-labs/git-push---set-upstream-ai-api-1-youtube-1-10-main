## 1. 固定する要件と進め方

- 題材は日常に関わる概念・知識。時事・経済ニュースから基礎用語へつなぎ、生活への活かし方まで説明する。架空例と実際の出来事を区別する。

- 顔出し・アバターなし。本人の属性を公開しない。
- 字幕は焼き込み希望。構成、題材を説明する動き、文字ずれ、サムネイルを改善する。単なる速度変更で終えない。

2. finish後にcheckを実行。scripts/verifyを使う場合もfinish後に実行する。
3. 新テーマのデモ生成と実再生、T104の未承認拒否/承認後進行/変更失効、T106の焼き込み字幕、T108の算術・出典を確認する。
4. 全テスト成功だけで、実再生・音声品質・本人承認まで成功したとは書かない。

### 停止・中断時
実行環境の制限や終了が近い場合は、最後に通った検証、未完の小単位番号、次のコマンド、変更ファイル、残件を保存してpausedでfinishする。再開時はcheckとチケットを読み、新しい作業回から続ける。人の返答待ちだけなら当該項目をreview等で残し、独立した残りのチケットへ進む。

## 7. 最終引渡し

最終応答とリポジトリ内の引継ぎ文書には以下を含める。
- 4チケットそれぞれの実装結果・状態・検証・未検証。reviewをdoneの件数へ含めない。
- 試作動画と画像、比較資料の場所。既存制作物を消していないこと。
- 本人が実施する題材選定・考察入力・台本承認・動画確認の具体的な操作例。
- 再生成/起動/テスト/途中再開のコマンド。
- 本人に残る判断だけを質問形式でまとめる。課金・契約・投稿の許可を混ぜない。

目標は「1回の依頼で、エージェントが担当できる全実装・検証を進め、必要な人の判断だけを最後にまとめる」こと。実行していない試験や本人の確認を完了扱いにして、形式上だけ全件doneにしない。
