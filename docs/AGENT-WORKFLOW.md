# エージェント共通の作業・ログ運用
すべてのAIエージェントに同じ手順と検査を適用します。特定サービスのSDK、チャット継続、アカウントは不要です。チケットの担当はhuman / agent。実施者・記録者・モデルは作業ごとに指定し、エージェント名に許可リストや優先順位を設けません。

## 初回準備
Node.js 24以上とGitを用意してください。`scripts/run` はPATHのnodeを使用します。別の実行ファイルを選ぶ場合は `export NODE_BIN=/path/to/node` と明示します。保存済みのユーザー専用パスやCodex付属Nodeを自動選択することはありません。Windows等でshがない場合はリポジトリルートで `node src/worklog-cli.ts ...` / `node src/cli.ts ...` を直接実行できます。動画描画は引き続きmacOS限定で、これはエージェント管理の制約とは別です。

```sh
./scripts/install-hooks
```
現在のcloneだけでGitのpre-commit検査を有効化します。cloneし直した場合は再実行。既存フック設定は上書きせず停止します。既存フックがある場合は、その管理者が既存処理に `./scripts/run src/worklog-cli.ts check --staged` を追加してください。Windows環境ではGit for Windowsのsh等が必要です。

## 作業開始
README、SPEC、STATUS、対象チケットと依存、AGENTS.mdを読みます。
```sh
./scripts/run src/cli.ts check
./scripts/run src/cli.ts next
./scripts/run src/worklog-cli.ts start T020 --agent '使用するエージェント名' --model '実際のモデル名またはunknown' --model-source unknown --request '今回の依頼と許可範囲'
```
`model-source` はruntime（実行環境で確認）/ user-specified（利用者指定）/ unknown（不明）。不明なモデルを推測して書きません。既存の未終了ログがあれば開始を拒否し、担当交代時も引き継いで先に記録を閉じます。単一作業ツリーで同時に複数タスクを開始しない運用です。開始はチケット状態を勝手に変更しません。

返された `logs/<UTC日付>/<時刻-Ticket-ID>/` にsession.jsonとWORKLOG.mdができます。今回から日時はUTCで統一し、過去ログのAmerica/Los_Angeles表記は当時のまま保存します。

## 作業中
対象チケットをin_progressにし、実装・検証します。必要な結果と秘密を含まない出力を作業ログディレクトリに保存。WORKLOG.mdの全必須節を具体的に埋めてください。試験未実施や残件なしの場合も、その事実と理由を書きます。TASKの状態の正本はticketsで、ログは時点記録です。

## 終了・中断（すべてのエージェントで必須）
コミット前に `./scripts/verify`（check・テスト・型検査。motion-labの試験・型検査を含み、その依存が未導入なら失敗する。意図して省く場合だけ `VERIFY_SKIP_MOTION_LAB=1`）を実行する。作業回が開いている間は先頭のcheckが「未終了作業」で止まるため、終了前はテストと型検査を個別に実行し、終了後にverifyを通す。pre-commitフックはログ検査だけを行う。
1. チケットの結果・証跡・状態を更新。条件を満たした場合だけdone、確認待ちはreview。
2. docs/STATUS.mdに再開地点を記録。
3. WORKLOG.mdの依頼、変更、理由、検証、未実施、TODO・再開を埋める。
4. 次を実行し、成功してから利用者へ終了報告する。
```sh
./scripts/run src/worklog-cli.ts finish logs/<日付>/<作業ID> --status completed
./scripts/run src/cli.ts check
```
中断・作業交代時は `--status paused` を使用。作業ログのcompletedは「この作業回の記録を閉じた」の意味であり、チケットがdoneであることを意味しません。人の確認待ちでも残件を明記して作業回を閉じられます。終了後にファイルを変更したら新しい作業記録をstart/finishしてください。閉じたログや証跡を黙って編集しません。

## 自動的に拒否するもの
- finish時（T013以降）: 節どうしの本文が同一のログ、本文がevidenceを参照しているのにevidence/が空のログ。終了済みの過去ログには適用しない。
- ファイル名とidが一致しないチケット。チケットとログのCRLF改行は受理する。
- 終了ログなし、未終了セッション、存在しないチケット。
- 記録者・モデル情報不足、必須節なし、ひな型の未記入。
- 終了後のログ本文/証跡の変更・追加・削除。
- 最終終了時点と異なるコード・設定・文書・チケットの追加/変更/削除（SHA-256）。過去の手作業ログも対象。
- コミット対象のindexにログがない、またはindexの内容と終了記録のハッシュが異なる場合。作業ツリーだけ整っていても通りません。

既存の回顧ログはそのまま保持し、session.json付きの新しい形式だけ終了検査の対象とします。ログ自身のディレクトリはソース一覧から外し、その本文と添付証跡を別ハッシュで検証します。制作物・work・秘密設定は読み取り対象外。依頼本文へ秘密値を書かないでください。一般文書中の秘密を自動判定・除去する機能ではありません。

## 異常終了からの復旧
プロセスが落ちてもopenのsession.jsonが残り、checkと次のstartが失敗します。WORKLOG.mdに中断までの事実、未検証、残件を記載し、ticket/STATUSも更新してpausedでfinishします。引継ぎ担当者は自分の名前を本文に追記して誰が復旧したか残してください。新しい作業回で再開。根拠なしにdoneに変更しません。

## 保証範囲と限界
規約・終了CLI・コミット前検査の三層で記録漏れを検出します。Gitに何も保存せず応答だけする外部AI、`--no-verify`、フック無効化、検査コード/証跡の意図的改変、OS強制終了後の自動作文まで強制できる仕組みではありません。ハッシュは改変の検知であり署名・第三者監査ではありません。ログに書かれた試験結果の真偽を自動証明しません。

より強い組織的強制は、外部リポジトリの必須CIチェックと保護設定が必要です。今回は外部公開・pushをせず、ローカルの仕組みまで導入。AI製品ごとの実機試験は未実施で、CLIに異なるエージェント名を渡す共通動作を試験しています。未対応モデル名でも同じ処理です。

## 定型作業の抽出
finish前に `.agents/skills/routine-to-skill/SKILL.md` を読み、今回の反復候補を評価してログへ記録します。新規作成だけでなく、既存更新・見送りを選べます。ログ終了手順は `.agents/skills/repository-task-closeout/SKILL.md` が補助します。Skillの追加や更新もfinishより前に済ませてください。リポジトリ内の原本を明示的に読む方式はどのAIでも共通です。個人のSkillディレクトリへ置いたコピーの自動発見は実行環境に依存します。
