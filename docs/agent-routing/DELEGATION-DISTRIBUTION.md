# Routerの推奨と他製品への委譲（2026-10-17、T121）

モデルの候補を選ぶことと、その製品で実行することは別工程。Hookの推奨表示や `agentctl plan` では現在の親モデルは変わらず、他製品も起動しない。親が作業を切り出して `agentctl run --task <task.json>` を呼ぶ必要がある。

プロジェクト全体ではAntigravityも使われていた。一方、調査時点の当該チャットは7作業回すべてCodex対話で、CLI委譲がなかった。既定方針は多くのtask_typeで `initiator`（起動元）を先頭に置き、条件を満たす最初のモデルを選んでいたため、Codex開始の仕事はCodexへ戻りやすかった。加えて、親が具体的な子作業をGatewayに渡さなければ、推奨があっても分担されない。

件数は実行開始時刻、使用量集計は記録時刻で範囲を切るため同一指標ではない。トークン、キャッシュ、API換算額、購読枠の使用率も同一視しない。未計測は0消費ではない。

## 利用者が希望した役割別の優先先

方針の正本は `orchestration/model-registry/routing-policy.json`、version `2026-10-17.1`。

| 作業 | 優先する製品 |
|---|---|
| 実装・アニメーション・描画・設計 | Claude → Antigravity → Codex |
| レビュー | Claude → Codex → Antigravity |
| 分析・抽出・分類・要約・一般作業 | Antigravity → Claude → Codex |
| 全体調整 | Codex → Claude → Antigravity |
| 動画解析 | 従来どおりAntigravity優先。Gemini APIは課金無効のため選択不可 |

能力・認証・品質tier・予算の条件を満たす候補だけを使う。同じtierに適格候補がなければ、既存Routerの規則どおり上位tierを探す。下位への自動引下げやAPI課金の有効化はしない。認証済みでも実行時に上限/認証エラーが出た場合の停止規則は維持し、無条件で別製品へ回し直さない。

この変更は利用者の分担希望に基づく優先順で、実績から最安・最高品質と判定したものではない。Optimizerの提案は必要な評価済みサンプルが不足し、no_changeだった。自動均等割当て、残り購読枠に応じた負荷分散、費用削減の保証は含まない。タスクの種類や実行可否によって偏りは残る。

変更前/後の方針は今回のevidenceのpolicy-before.json/policy-after.jsonに保存した。戻す場合も、`T121-provider-distribution-2026-10-17.patch` の逆パッチを一時コピーで検証し、`agentctl maintenance apply` で適用する。保護対象を直接書き戻さない。

## 親が実行すること

1. 独立した実装・調査・レビューを切り出し、担当ファイル・出力・必要検証を指定する。親は統合と最終確認を担当する。
2. Task schemaに従い `parent_task_id` を設定し、通常 `preferred_provider: null` でRouterに選ばせる。不要な全会話やログを複製しない。
3. `plan` で選択/認証/予算を確認してから `run` する。別製品への分担に製品内サブエージェントを使わない。
4. 子の成果を確認し、`status <task/execution ID> --require-metered` を通す。実行完了と成果の品質合格は分ける。必要なら `evaluate` で品質の不合格も記録する。
5. 実績が蓄積したらOptimizerの既存基準で評価する。親のCodex対話の消費は残るため、他製品の消費が発生しただけで全体効率が改善したとは断定しない。
