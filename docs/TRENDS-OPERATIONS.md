# トレンド・成長分析の運用（T135〜）

利用条件は [RESEARCH-TRENDS-API.md](RESEARCH-TRENDS-API.md)、指標は [TRENDS-METRICS.md](TRENDS-METRICS.md)。

## 履歴の保存方式（T135、`src/trends-store.ts`）
- 既定の場所は `work/trends/`（Git管理外）。本体 `store.json`、直前の正常な版 `store.json.bak`、実行中の排他 `store.lock`。
- 形式は `yt-trends-store/v1` の1つのJSON。収集batch（`yt-trends-batch/v1`）を追記し、ポリシー設定・削除の記録（件数のみ）・太平洋時間の日別クォータ使用量を持つ。数千件規模のローカル分析を想定し、外部DBは使わない（依存を増やさない）。
- 取込: 同じbatchIdは無視、同じ観測（出所/地域/対象/取得時刻/チャート位置）は重複として除く。同じ観測で値が違う場合や、同じbatchIdで内容が違う場合は**上書きせず停止**する。
- 保存: 一時ファイルへ書いてfsync、読み直して検査、正常な現行本体をバックアップへ写し、renameで置き換える。途中で落ちても本体かバックアップのどちらかが正常に残る。
- 排他: `store.lock` を排他作成する。残っている場合は、他の処理が動いていないことを確かめてから手で削除する。

## 保持と削除（T131の条件）
| ポリシー | 統計（再生数・登録者数など） | 統計以外（タイトル、公開日時、カテゴリ、カテゴリ名） |
|---|---|---|
| standard（既定） | 取得から30日で記録ごと削除 | 同左 |
| audited-derived-metrics（III.L承認の参照が必要） | 36か月で削除 | 30日で値を消す（IDと統計は残る） |
| 合成データ | 期限なし | 期限なし |

- 期限切れの削除は、収集・取込・レポートの前に毎回実行する（T134・T137のCLI）。削除した件数と時刻を `deletions` に残す。
- 利用者の指示による削除（動画・チャンネル・出所の指定）も同じ記録に残す。III.E.4.gの削除要求は7暦日以内に実施する。
- ポリシーをstandardへ戻すと、次の削除で30日の条件が再適用される。
- 承認後にタイトル・カテゴリを30日で消すため、古い観測はカテゴリ不明（unknown）として扱われる。カテゴリを長く使えるかは公式に記載がなく、保守的に消している【未確認】。

## 復旧
1. `store.json` が読めない場合、読み込みは自動でバックアップを使い、警告を出す。次の保存で本体が正常な版に置き換わる（壊れた本体はバックアップにしない）。
2. 本体とバックアップの両方が読めない場合は、書き込まずに停止する。`work/trends/` を別の場所へ退避し、書き出したファイル（下記）があればそれを `store.json` として戻す。
3. スキーマ版が `yt-trends-store/v1` 以外なら停止する。移行処理を実装するまで読み書きしない。
4. 本体がなくバックアップだけがある場合も停止する（誤って空の履歴で上書きしないため）。

## 書き出し
`exportStore` で出所の区別を保ったまま別ファイルへ書き出す。APIデータの書き出しも同じ保持期限に従い、期限後は書き出したファイルも削除する（書き出し先の管理は利用者の責任）。

## CLI（T137、`src/trends-cli.ts`）
```
./scripts/run src/trends-cli.ts help
```
| コマンド | 内容 |
|---|---|
| `status` | 出所・地域ごとの件数、最新時刻、ポリシー、太平洋時間の当日クォータ使用量 |
| `import <file.json>` | batch または `{batches:[...]}` を取り込む（例: `fixtures/trends/synthetic-history.json`） |
| `collect --fixture fixtures/trends/mock-api.json` | 模擬接続で収集（出所はsynthetic、クォータ台帳に数えない） |
| `collect --live [--dry-run]` | 実接続（`YOUTUBE_API_KEY` が必要。T133の承認範囲だけ）。`--dry-run` は見積りだけで送信しない |
| `report categories\|videos\|channels\|series` | 表（既定）・`--format csv`・`--format json`、`--out` でファイル出力 |
| `policy` / `policy set ...` | ポリシーの表示・記録（記録者 `--by` が必須） |
| `purge` / `delete` / `export` | 期限削除・指定削除・書き出し |

- すべてのコマンドは、開いた直後に保持期限の削除を行う。
- 終了コード: 0 成功、2 使い方の誤り、3 ポリシーで停止（APIデータの派生指標）、4 クォータ上限、5 認証・設定、6 一時障害（再試行上限）、7 不正な要求、8 予算（送信前の拒否・再試行で上限）、9 履歴のエラー（ロック・破損・スキーマ）。
- 収集が失敗しても履歴（収集データ）は変更しない。実接続で使ったunitは失敗時も台帳へ記録する。
- CSVは先頭の `#` 行に出典・観測期間・鮮度・指標の意味・限界を書く。`=`・`+`・`-`・`@` で始まる文字列には `'` を付け、表計算ソフトで式として実行されないようにする。
- 実データでの運用例（T133・III.L承認の判断後）:
  1. `export YOUTUBE_API_KEY=...`（値はシェルの秘密管理から。コマンド履歴・ログに残さない）
  2. `./scripts/run src/trends-cli.ts collect --live --dry-run --pages 1 --no-categories --no-channel-stats` で見積りを確認
  3. 承認範囲内なら `--dry-run` を外して1回実行し、`status` で使用unitを確認
  4. standardのままなら `report series --source youtube-data-api --video <id>`（取得値の推移）だけが使える
