# 起動・停止・復旧
1. READMEのcheckとtestを実行。nextで作業を選ぶ。
2. sampleで新ジョブ作成。途中状態はoutputs/<id>/job.json。
3. serveを起動しローカルで再生。停止はCtrl+C。

## 失敗
- Nodeがない: Node 24以上をPATHに配置。scripts/runの予備経路は今回の端末用。
- Swiftがない: MacのCommand Line Toolsを用意する。インストールは利用者の環境設定作業。Linux/Windowsは未対応。
- FFmpegがない: scripts/setup-mediaを実行。ネットワーク不要の運用は初回取得後から。
- encode失敗: job.jsonのerrorを確認。完了扱いにはならずlatestは前の成功のまま。ディスク空き容量と入力を確認してsampleを再実行。途中再開は未実装。
- 強制終了: job.jsonがrunningのまま残ることがある。`cli.ts jobs` で「中断の疑い」を確認し、`jobs abandon <id> --note 文` で記録してから新ジョブを作る（T033）。古い成果物を再利用しない。
- 再生できない: sample.mp4の存在を確認。別のローカル動画プレーヤーで試す。serveのポート4173が使用中なら既存の自分のサーバーを停止する。
- 文言変更: fixtures/sample.jsonを編集しversionを増やす。文字数・場面数・時間の検証に従う。新しいjobとして再生成しT006相当の検査を行う。
- コンパイラ更新後: work/renderとwork/render-sourceを削除して再生成。Swiftキャッシュはwork/swift-cache。

## 保管
outputsとworkはGit対象外。残したいサンプルはローカルの別保管先にコピーする。大量動画の履歴管理はしない。DBなし。設定・台本・コードのバックアップはローカルGitを利用し、動画が必要なら別途バックアップする。復元はソース・fixtureからsetup/sampleを実行。鍵をバックアップへ混ぜない。

M5の全停止、永続進捗、自動再開、予算予約の永続化（実行中の予約・費用不明額はプロセス内のみ。T098）、通知、未開始監視、外部投稿照合、異常注入試験は未実装。このCLIを無人投稿用として運用しない。

## ジョブの確認・承認・管理（T033、2026-10-08）
- `./scripts/run src/cli.ts serve` → http://127.0.0.1:4173/ に一覧が出る。詳細画面で、動画（ソフト字幕は<track>で表示）、安全検査、媒体検査、台本、確認の履歴を見られる。
- 承認・差戻しは画面のボタン、または `cli.ts review <id> approve|reject --hash <現在の版（review <id> で表示される一式の版）> [--note 文] [--reviewer 名前]` で行う。
  - 承認は確認対象一式の版に結び付く（T095）。一式は、完成動画、採用タイトル・概要欄・タグ・チャプター（metadata.json）、字幕（subtitles.vtt）、サムネイル案の全案。どれかが変わる・欠ける・増えると失効（expired）する。差戻しには理由のメモが必要。
  - 採用サムネイルを選ぶ機能がないため、当面は3案すべてを承認対象にする（1案を差し替えても失効する）。台本（plan.json）、検査記録、見直し履歴（metadata-revisions.json）、review.json、job.jsonの付帯情報は対象外で、変えても失効しない。
  - `cli.ts metadata <id> revise` でタイトルを見直すと承認は失効する。もう一度画面で確認して承認する。
  - T095より前の承認（動画のハッシュだけに結び付いた旧形式）は、一式へ自動で広げず「旧形式の承認。再確認が必要」と表示する（expired）。過去のreview.jsonは書き換えない。
  - 記録は <job>/review.json に追記される。投稿はしない。
  - エージェントが動作確認で記録するときは、--reviewer にエージェント名を入れる。人の承認と混同しないため。
- `cli.ts jobs` で一覧を出す。runningなのにプロセスがないジョブは「中断の疑い」と表示される。`jobs abandon <id> --note 文` でabandonedにする（動作中のプロセスがあれば拒否）。
- `cli.ts jobs clean` は退避候補の表示だけ。`--apply` で移動する。failed/abandonedのジョブは outputs/_trash/、直下の散らかったファイルは outputs/_archive/<日付>/ へ移る。削除はしないので、元に戻すときはディレクトリを戻せばよい。
  - 復元先: `_trash/<ジョブID>` は outputs/<ジョブID> へ、`_archive/<日付>/<名前>` は outputs/<名前> へ戻す。移動先は `移動: 元 → 退避先` と表示される。
  - 衝突時（T094）: 退避先に同名のファイル・ディレクトリ（空のディレクトリやsymlinkも含む）が1件でもあれば、どれも移動せずにエラーで止まる。上書き・自動の別名付けはしない。同日に同名のファイルを再び退避したいときは、退避済みのものを確認して別名にするか別の場所へ移してから再実行する。
  - 途中で失敗したとき（権限や消えたファイルなど）は、エラーに「移動済み: 元 → 退避先」の一覧が出る。一覧にない項目は元の場所に残っている。

## 見やすさの確認（T091、2026-10-08）
- 本番は `sample --resolution 1080` で1920×1080を出力する。座標は720p基準のまま、1.5倍で描く。
- 自動検査の結果はjob.json.readabilityに残り、確認画面の「見やすさ」の節に出る。
  - 最小文字サイズ: 720p換算16pt以上。研究の根拠はない暫定値。
  - 文字と背景のコントラスト比: 4.5以上（WCAG 2.x AA）。
- 人の確認（公開前に1回。結果を確認画面の承認メモに書く）。
  1. スマートフォンで全画面にせず縦向きのまま再生し、見出し・図解・強調の札が読めるかを見る。
  2. テレビ（またはPCを2〜3m離れた位置）で再生し、字幕（ソフト字幕をオンにした状態）と図解の小さい文字が読めるかを見る。
  3. 読みにくい箇所があれば、場面番号と要素をメモし、台本の文言を短くするか、強調語を減らす。
- 背景: 日本では50代の83.0%、60代の71.2%がYouTubeを利用し（G32）、テレビでの視聴時間は3年で2倍超（G33）。
